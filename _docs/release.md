# Релиз для игроков

Название для игроков: **CM0102 Display Fix** (техническое имя внутри — cmfix: `dsound.dll`, `cmfix.ini`, `cmfix.log`).

Сборка: `python _tools\release\release.py`. Скрипт собирает cmfix и пишет `_release\CM0102-Display-Fix-<версия>.zip` и `CM0102-Display-Fix-<версия>.sha256.txt` (хеши каждого файла и архива). Папка `_release` не в git. Версия берётся из `CMFIX_VERSION` в [cmfix.c](../_tools/cmfix/cmfix.c), её же cmfix пишет в первой строке `cmfix.log`.

Архив распаковывается в папку с `cm0102.exe`:

| Файл | Откуда |
|---|---|
| `ddraw.dll` | cnc-ddraw 7.1.0.0 (`_downloads`) |
| `ddraw.ini` | ini cnc-ddraw с ключами `[ddraw]` профиля [release.json](../_tools/wrappers/release.json) |
| `Shaders/omniscale/omniscale.glsl` | из пакета шейдеров cnc-ddraw, лицензия MIT внутри файла |
| `dsound.dll`, `cmfix.ini` | `_tools\cmfix` |
| `README-CM0102-Display-Fix.txt` | [_tools/release/README.txt](../_tools/release/README.txt), `{version}` подставляется |
| `licenses/cnc-ddraw-LICENSE.txt` | MIT, из репозитория cnc-ddraw |

Профиль `release` — это `cnc_play_fix` плюс `cmfix.ini` (text4k включается файлом, без переменной окружения) и `width=0`/`height=0` вместо 2400×1800 из dev-профилей (такое окно не влезло бы на экран 1080p). cnc-ddraw тогда открывает окно 800×600, и cmfix один раз при первом появлении окна такого размера увеличивает его до самого большого 4:3, которое помещается в 85% рабочей области монитора (на 4K с рабочей областью 3840×2064 это 2336×1752). Если `width`/`height` в `ddraw.ini` заданы (в `[ddraw]` или `[cm0102]`), cmfix окно не трогает, поэтому dev-профили с 2400×1800 ведут себя как раньше. Тот же набор ставится в dev-папку командой `python _tools\play.py release`.

Проверено вживую 2026-10-17:

- `play.py release`: окно с `width=0` открывается 800×600 и примерно через секунду подгоняется до 2336×1752 по центру; ресайз, разворот и восстановление работают.
- Установка в основную установку `C:\Games\CM0102` (чистый 3.9.68) распаковкой архива, запуск `cm0102.exe` двойным кликом: чёткий текст, Screen Mode, Alt+Enter, подгонка окна, сохранение и загрузка под новым именем. Удаление по списку из README возвращает игру к прежнему виду.
- Exe с патчем разрешения 1280×800 (воспроизведение лоадера, см. compat_patches.md): text4k сам уступает текст игре, новая игра и загрузка работают.
- Отдельная копия игры в другой папке для такой проверки не годится: игра делает chdir в путь из реестра (`Location`), см. phase1_report §2.5.

Перед публикацией не решено и не проверено:

- лицензия на свой код, страница с исходниками (README ссылается только на хеши);
- проверка архива на VirusTotal.

## На потом

- Чёткий текст при патчах разрешения (1280×800, 1024×576, «несколько разрешений» из CM0102Patcher). Сейчас text4k при кадре не 800×600 выключается. Нужно: размер кадра и масштаб брать из back-buffer, учесть не 4:3 кадры; высоту строк брать у игры (`0x5E5CD0`) вместо копии таблиц T2K (патч переписывает метрики `0x5E5CEA–0x5E5D22`; заодно это переживёт «шрифт +1»); пройти все экраны в каждом разрешении. Код около дня, основное время — проверка. Решено отложить до отзывов после первого релиза.
