# Phase 2b spike: «настоящий» чёткий текст поверх увеличенного кадра

Дата: 2026-10-17. Цель: выяснить, реально ли перехватывать вывод текста игры и рисовать его заново в 4K. Саму перерисовку не делали.

**Вывод: реализуемо.** Весь экранный текст проходит через одну функцию, у неё простые аргументы. Игра рисует строки прямо в единственный back-buffer, кэшированных панелей с текстом нет. Списки при прокрутке перерисовываются целиком, пиксели не сдвигаются. Главная неизвестная — не игра, а встраивание своего слоя в вывод cnc-ddraw (см. «Что осталось проверить»).

## Что нашли (cm0102.exe 3.9.68)

Вся графика игры собрана в одном модуле `0x5E2620–0x5E8290`. Он работает с двумя поверхностями DirectDraw:

| Адрес | Что это |
|---|---|
| `[0xAE31A4]` | primary surface |
| `[0xAEBDE4]` | **back-buffer**: offscreen 800×600 16 bpp (caps `0x840` = SYSTEMMEMORY\|OFFSCREENPLAIN), создаётся в `0x5E2620` (gfx init). Других поверхностей игра не создаёт, этот указатель больше нигде не меняется |
| `[0xAEBE0C]` | флаг «графика выключена»: все примитивы при ≠0 сразу выходят |
| `0xAE1DAC + id*0x1404` | таблица растровых шрифтов `.fnt` (id 1..7 = arial_narrow_10, arial_narrow_11, arial_14, arial_16, arial_18, trade_cond_24_bold, trade_cond_28_bold; грузит `0x5E4A60` → `load_font 0x5E4BA0`) |
| `[0x9CC2C4]` | выбор шрифта: −1 → растровые `.fnt`, иначе движок T2K (`small/medium/large.t2k`, объекты `0xAEBDF4/F8/FC`, `0xAEBE00`, растеризация `0x5B0D80`) |

Функции текста:

| Адрес | Сигнатура (cdecl) | Роль |
|---|---|---|
| **`0x5E5160`** | `draw_string(int x, int y, short font, u16 color565, const char *s, int caret)` | **Единственная точка, где рисуются глифы.** Lock `[0xAEBDE4]` → попиксельно (`.fnt`: 4-битная альфа с блендом по фону) либо T2K → Unlock. `(x, y)` — левый верхний угол ячейки строки. `caret ≥ 0` — рисует курсор ввода после символа № caret. В строке `|` → пробел, `#hhhh#` — встроенный цвет (`0x5E5060` переводит строку в u16). Вызывается только из `0x5E6D80` |
| `0x5E6D80` | `draw_text_box(x0, y0, x1, y1, flags, font, color, const char *s, …)` | Перенос по словам и выравнивание в прямоугольнике кнопки или ячейки. Рисует тень `draw_string(x+1, y+1, тёмный цвет)` (возврат `0x5E747F`), затем саму строку (возврат `0x5E75FC`). 11 прямых вызовов из UI (`0x5EEBxx` и др.) |
| `0x5E5AD0` | `text_width(font, s)` | Ширина строки, 64 вызова: пригодится для подгонки нового шрифта к старой ширине |
| `0x5E5D60` / `0x5E5CD0` | ширина символа / высота шрифта | |

В режиме T2K высоты строк и размеры (pt) берутся из таблиц переходов по `font`: 15/18/21/24/27/39/45 px и 9/9/10/14/16/18/20/22 pt. Точное соответствие номерам не сверялось. Шрифт 0 содержит иконки: стрелки ←/→ в левой панели — это глифы `(` и `)` шрифта 0.

Остальные примитивы того же модуля (все Lock-и-пишут в `[0xAEBDE4]` CPU-кодом):

| Адрес | Роль |
|---|---|
| `0x5E2EB0` | `present_rect(x0,y0,x1,y1)`: BltFast back → primary для «грязного» прямоугольника (22 вызова) |
| `0x5E3DD0` | `grab(x0,y0,x1,y1, saved*)`: копия прямоугольника back-buffer в malloc `{w,h,bytes,pixels}` |
| `0x5E3FD0` | `put(x,y, saved*)`: копия обратно в back-buffer (26 вызовов) |
| `0x5E3730` | линия/прямоугольник `(x0,y0,x1,y1, mode, color)`: рамки кнопок (25 вызовов) |
| `0x5E42E0`, `0x5E5DF0`, `0x5E7840`, `0x5E3CE0`, `0x5E7F60`… | заливки и картинки (не разбирались подробно) |

## Проверка вживую

Временный лог-хук в cmfix (`#ifdef CMFIX_TEXTLOG`, обычная сборка `build.bat` его не включает). Это in-memory detour на `0x5E5160`, `0x5E6D80` и на `present/grab/put/rect`, с проверкой байт пролога. Лог: `cmfix_text.log`. С `CMFIX_TEXT=hide` хук не даёт `draw_string` ничего нарисовать. Запуск: временный профиль `_tools\wrappers\spike_textlog.json` (`cnc_play` + `_tools\cmfix\build_textlog\dsound.dll`). Сборка: в `build.bat` добавить `/DCMFIX_TEXTLOG` и `build_textlog\` вместо `build\`. Захват: scenario/`frame()` в режиме `fit_aspect` (экран, не `--desktop`).

1. **Главное меню: координаты совпадают.** 19 `BOX` и 27 `DRAW` (полный лог: `phase2b/main_menu_text.log`). Крест в `(x, y)` из лога стоит точно в левом верхнем углу каждой надписи, прямоугольники `BOX` совпадают с рамками кнопок: `phase2b/main_menu_coords.png`.
2. **Весь текст идёт через `0x5E5160`.** С `CMFIX_TEXT=hide` на кадре не осталось ни одной надписи, включая заголовок, неактивную «Add Manager» и стрелки. Рамки и фон на месте: `phase2b/main_menu_hide.png` (слева обычный кадр, справа hide; фоновая фотография случайная).
3. **Прокрутка списка (Select League(s), 2 клика по стрелке).** Каждый шаг анимации выглядит так: `put` фона области списка (110,170, 649×366), затем `draw_string` всех видимых строк на новых y, затем `present_rect` области. Пиксели текста не сдвигаются и не копируются.
4. **Модель «сцены» сходится с кадром.** Простая модель по логу: `DRAW` добавляет элемент, `put`, перекрывший его точку `(x, y)`, удаляет. После 2440 вызовов (меню → лиги → прокрутка) в ней осталось 74 элемента. Они в точности совпадают с текстом на итоговом кадре, лишних и пропавших нет: `phase2b/leagues_scene_after_scroll.png`.

## Back-buffer или кэш?

Текст всегда рисуется прямо в back-buffer `[0xAEBDE4]`. Своих поверхностей или буферов для панелей и списков нет. Кэш есть только у фона. Виджет при первом показе делает `grab` своего прямоугольника (фон под ним), при перерисовке — `put` этого фона и рисует рамку и текст заново. Смена экрана начинается с `put` полноэкранного фона 800×600. Отсюда простое правило: любая запись пикселей поверх bbox надписи (`put`, заливка, картинка) снимает надпись со сцены, новый `draw_string` добавляет её снова. `grab` может захватить пиксели надписи, только если текст уже нарисован. Если исходные глифы подавлять (режим hide), в кэш они не попадут вовсе, и картина остаётся согласованной.

## Как могла бы выглядеть реализация

1. Хук `draw_string` в cmfix пишет в сцену `(x, y, font, color, строка, тень/не тень)` и не рисует глифы (кроме шрифта 0 с иконками, который можно оставить растровым). bbox считается по `text_width` (`0x5E5AD0`) и высоте шрифта.
2. Хуки на 10–15 пиксельных примитивов модуля `0x5E2xxx–0x5E8xxx` удаляют из сцены перекрытые надписи. Так покрываются попапы, выпадающие списки и подсказки.
3. Снимок сцены берётся в `present_rect`. Рендер-поток cnc-ddraw после своего шейдера (OmniScale) рисует сцену в 4K-координатах (масштаб = ширина кадра 4:3 / 800, на 4K это 3.6) шрифтом TrueType с атласом глифов. Тень рисуется со сдвигом в 1 игровой пиксель. Ширина строки подгоняется к исходной ширине (`text_width × scale`), чтобы не ломать вёрстку.

## Что осталось проверить (риски)

- **Встраивание в вывод cnc-ddraw** (renderer=opengl): нужен свой проход после масштабирования и до `SwapBuffers`, например IAT-хук `SwapBuffers`/`wglSwapBuffers` модуля ddraw.dll или переход на `renderer=direct3d9` и хук `Present`. Не проверялось. Это основная техническая неизвестная. Запасной вариант без встраивания — рисовать текст в своём слое-окне поверх игры, но это хуже (синхронизация, Alt+Tab).
- Межпотоковая передача сцены (игровой поток → рендер-поток cnc-ddraw): двойной буфер под lock, переключение в `present_rect`.
- Не просмотрены: экран матча (2D-движок), выпадающие списки, подсказки, поля ввода (caret), экраны с `#hhhh#`-цветами, режим `.fnt` против T2K (оба идут через `draw_string`, но метрики разные).
- Метрики: замещающий шрифт должен влезать в ту же ширину, иначе текст наедет на соседние колонки. Лечится сжатием по ширине.

## Оценка объёма

- MVP (меню и списки, хук `draw_string` с подавлением, инвалидация по `put`/заливкам, оверлей в cnc-ddraw через GL, растеризация TrueType): **3–5 дней**, из них 1–2 на встраивание в cnc-ddraw.
- Доводка (все примитивы, попапы, матч, caret, цветовые коды, подгонка метрик, артефакты на краях): **ещё 3–5 дней**.
- Первый шаг: 0.5–1 день на проверку встраивания в cnc-ddraw (нарисовать в 4K одну строку поверх OmniScale-кадра). Если встроиться не получится, вся идея упирается в это.

# Phase 2b: реализация text4k (MVP)

Дата: 2026-10-17. Код: [_tools/cmfix/text4k.c](../_tools/cmfix/text4k.c), собирается вместе с cmfix (`build.bat`). Запуск:

    python play.py cnc_play_text4k

Профиль `cnc_play_text4k` — это `cnc_play_fix` плюс `CMFIX_TEXT4K=1` в окружении игры. Поле `"env"` профиля передают `play.py` и `scenario.py`. Игрокам переменная не нужна: те же настройки читаются из `cmfix.ini` рядом с `dsound.dll`, секция `[cmfix]`, ключ = имя переменной без `CMFIX_` (`text4k=1`, `text4k_font=…`). Образец: [_tools/cmfix/cmfix.ini](../_tools/cmfix/cmfix.ini). Переменная окружения важнее файла. Без того и другого (обычный `cnc_play_fix`, в dev-папке `cmfix.ini` нет) модуль не включается, поведение прежнее.

## Как устроено

- **Игровой поток.** Хук `draw_string` (`0x5E5160`) не рисует глифы, а записывает строку в сцену: x, y, шрифт, цвет, ширину по `text_width` и высоту строки. Вместе со строкой сохраняется контрольная сумма фона под её прямоугольником. Тень игра рисует отдельным вызовом, и она попадает в сцену как обычная строка.
- **Какие строки видны.**
  - Новая строка удаляет пересекающиеся строки, нарисованные до предыдущего present: пересекаться должны полосы самих букв, поля строк не в счёт (нажатая кнопка «Action» задевает поле имени в шапке). Удаление происходит, только если фон под старой строкой в месте пересечения не изменился ни на пиксель (игра переписала надпись на том же фоне). Если между ними что-то нарисовали, например подложку меню, старая строка просто перекрыта и вернётся, когда меню закроют.
  - `put` (`0x5E3FD0`) удаляет строки, целиком лежащие в его прямоугольнике. Частично задетые строки остаются, а видимость их частей решает проверка по полосам (см. ниже). Иначе имя игрока, через которое тащат плашку позиции на экране состава, пропадало до следующей перерисовки списка.
  - `grab` (`0x5E3DD0`) запоминает, какие строки лежали в сохранённом куске. Последующий `put` того же буфера возвращает их на место, со сдвигом, если кусок кладётся в другое место. Буфер узнаётся по адресу и хешу пикселей: игра переиспользует память.
  - В `present_rect` (`0x5E2EB0`) строки в показываемом прямоугольнике сверяются с сохранённой копией фона под буквами. Сравнивается только средняя половина высоты строки, по вертикальным полосам в 16 игровых пикселей. Полоса скрывается, если изменилось больше 30% её пикселей: так бывает с кнопками, попапами и меню. Тонкие линии (пунктирная рамка перетаскиваемой позиции на экране состава) и задетые поля сверху и снизу буквы не скрывают. Длинные имена в шапке профиля, заходящие под кнопку «Action», показываются целиком.
- **Окна поверх экрана** (найдено зондом `CMFIX_TEXT4K_PROBE=1` при открытии Team Instructions):
  - `0x5E42E0 dim(x0,y0,x1,y1)` затемняет прямоугольник: весь экран под окном. Надписи под затемнением рисуются темнее (65% / 45% / 30% яркости при повторном затемнении), как тускнеют буквы в оригинале, а не скрываются.
  - `0x5E5DF0 panel(x0,y0,x1,y1, флаги, цвет)` с флагом `0x10` рисует полупрозрачную текстурную панель: тело диалога или выпадающего меню. Над похожим по цвету фоном (тёмно-зелёное окно над тёмно-зелёным полем тактики) пиксели почти не меняются, и проверка по пикселям её не видит. Поэтому панель от 200×150 закрывает надписи, чьи буквы лежат под ней. Панели с другими флагами (`1`, рамки, градиенты) игра рисует поверх видимых подписей, их правило не трогает.
  - Затемнение и закрытие снимаются, когда возвращается фон, сохранённый до них (окно закрыли). `put` фона, сохранённого позже (виджет внутри окна перерисовывает себя), их не снимает.
- **Поток рендера cnc-ddraw.** IAT-хук `gdi32!SwapBuffers` в `ddraw.dll`. После того как cnc-ddraw нарисовала кадр (OmniScale), сцена рисуется в его viewport (на 4K это 2880×2160 со смещением 480; контекст compatibility 4.6). Каждая строка растеризуется через GDI (сглаживание в градациях серого, кэш текстур на 768 строк), цвет берётся из RGB565 игры. Строка не бывает шире исходной: если наш шрифт шире, текстура сжимается по горизонтали. Состояние GL сохраняется и восстанавливается.
- **Шрифты.** Игровой «Futuristic» — это Eras Bk BT Demi (small/medium.t2k) и HandelGothic BT (large.t2k). Их глифы сжаты в формате T2K, Windows их не загрузит. Поэтому используется системный **Eras Demi ITC** (`ERASDEMI.TTF`, ставится с MS Office) с тем же рисунком. HandelGothic в системе нет, крупные заголовки тоже рисуются Eras. Настройки (переменная окружения или тот же ключ в `cmfix.ini`, см. выше):
  - `CMFIX_TEXT4K_FONT` / `CMFIX_TEXT4K_FONT_LARGE` — гарнитура;
  - `CMFIX_TEXT4K_WEIGHT_LARGE` — насыщенность крупных шрифтов;
  - `CMFIX_TEXT4K_EM` — коэффициент размера, по умолчанию 1.33;
  - `CMFIX_TEXT4K_YOFF` — сдвиг по вертикали в игровых пикселях;
  - `CMFIX_TEXT4K_DEBUG=1` — лог `grab`/`put` в `cmfix.log`.
- **Страховка.** Пока слой не отрисовал хотя бы один кадр (то есть cnc-ddraw не на OpenGL), игра рисует глифы сама. Худший случай — обычный низкорезовый текст, а не пропавший.
  - Если шрифта `text4k_font` нет в системе (проверка `EnumFontFamiliesExA`, только TrueType), text4k не включается: запись в `cmfix.log`. Проверено вживую 2026-10-17: `cmfix.ini` с `text4k=1` включает text4k без переменной окружения, а с `text4k_font=No Such Font` игра идёт с обычным текстом и пишет это в лог. Если нет только `text4k_font_large`, заголовки рисуются основным шрифтом.
  - Если back-buffer игры не 800×600 (патчи разрешения CM0102Patcher/Loader, см. [compat_patches.md](compat_patches.md)), `draw_string` отдаёт текст игре и пишет размер кадра в лог один раз.

## Известные ограничения

- Под затемнённым фоном модальных окон (Game Settings) надписи меню пропадают. В оригинале они видны тускло: игра затемняет пиксели вместе с текстом.
- Остаются низкорезовыми, их рисует сама игра: строки со встроенными цветами `#hhhh#`. Поле ввода во время редактирования (строка с курсором) text4k рисует сам, курсор ставит оверлей после символа № caret по ширинам Eras; `text4k_input=0` отдаёт такие строки игре.
- Заголовки рисуются Eras вместо HandelGothic: начертание «Championship Manager 2001/02» отличается.
- Без Eras Demi ITC в системе text4k выключается сам (см. «Страховка»); свободной замены пока нет.
- Шрифты Traditional (`.fnt`, Arial / Arial Narrow) text4k не трогает: при `[0x9CC2C4] == −1` строки рисует сама игра, как без cmfix. Переключение шрифта в игре работает на ходу: при переходе на Traditional сцена очищается, а `put` не возвращает надписи, сохранённые во время Futuristic. Причина: в первой версии с Traditional были три бага, которых нет в чистой игре (проверено на `cm0102_GDI.exe` 2026-10-17). Буквы с акцентами превращались в кириллицу («Svдrd», «Tourй», «£» → «Ј»), буквы были узкими и высокими, а у части счетов на экране «Evening Results» пропадала первая цифра.
- Строки растеризуются как Windows-1252 (`MultiByteToWideChar(1252)` + `TextOutW`, шрифт `ANSI_CHARSET`). Раньше были `TextOutA` и `DEFAULT_CHARSET`: на системе с кодовой страницей 1251 Arial выбирал кириллицу, Eras спасало только то, что в нём кириллицы нет.
