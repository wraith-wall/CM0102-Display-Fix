Всего разобрано около 76 тысяч записанных байт. Форматы `.patch`: `XXXXXXXX: OO NN`, `XXXXXXXX OO NN`, `0xXXXX 0xOO 0xNN` (смещение в файле), плюс команды (`EXPANDEXE`, `APPLYMISCPATCH`, `CHANGECLUBDIVISION`…), которые код в наших местах не меняют. В `cm0102.exe` 3.9.68 смещение в файле = VA − 0x400000 для `.text`/`.rdata`/`.data`. Скрипт проверки лежал в scratchpad сессии (`xcheck.py`), его логика: собрать все пары (смещение, длина) и пересечь с нашими адресами.

Сверено с релизной сборкой CM0102Patcher v2.31 (20.12.2025, `CM0102Patcher.exe`, SHA256 `bf740db0…a50b0f`, .NET, не запускалась): встроенный в неё набор патчей (903 записи) побайтно совпадает с `MiscPatches.zip` из GitHub, в GitHub есть ещё папка «2026 Patches». То есть проверка по GitHub покрывает и эту сборку.

## Результат

- **Точки хуков** (`0x5E2620`, `0x5E2EA0`, `0x5E5160`, `0x5E2EB0`, `0x5E3DD0`, `0x5E3FD0`, `0x5E42E0`, `0x5E5DF0`): ни один патч их не трогает.
- **Адреса данных** (`0x9CD808`, `0xB67A2C`, `0xAE319C`, `0xAEBDE4`, `0x9CC2C4`, `0xAEBE0C`): не трогает ни один.
- **Графический модуль `0x5E2620–0x5E8290`** меняет только смена разрешения: `to1280x800` (лоадер и патчер) и `ResolutionChanger` (любое разрешение). Она переписывает аргументы инициализации графики (`0x5D79EE` и др.: 800×600 → 1280×800), метрики шрифтов `0x5E5CEA–0x5E5D22` и множители строки back-buffer `0x5E7B72…`. Прологи наших функций остаются прежними, поэтому **хуки встанут, а text4k, рассчитанный на кадр 800×600, будет рисовать неправильно**. Поэтому text4k проверяет размер back-buffer и при кадре не 800×600 отдаёт текст игре (сделано). Проверено вживую 2026-10-18: копия exe с патчами лоадера `tapanispacemaker` + `to1280x800` (в том же порядке, байты из `CM0102Loader.cpp`, у `.data` в файле добавлен флаг исполнения, как у лоадера в памяти) и его картинками `Datakg1280_800.rgn`, `g800.mbr`, `m800.mbr`, запуск с релизным профилем. Игра идёт в 1280×800, в `cmfix.log` строка `text4k: game frame is 1280x800, not 800x600; text left to the game`, текст пиксельный и на месте, новая игра и загрузка работают. Без `tapanispacemaker` игра вылетала при старте новой игры: 1280×800 пишет код в место, которое освобождает этот патч.
- **`Increase_Font_Size_By_1`** пишет по `0x55FA14` (вне модуля) и в добавленную `EXPANDEXE` секцию: сдвигает номер шрифта на +1. text4k берёт номер шрифта и ширину строки у игры, так что должен это пережить. Вживую не проверялось.
- **`ScoreboardPatch`** (`0x719xxx`): табло матча, вне модуля.
- **CM0102Loader** запускает игру через `CREATE_SUSPENDED`, пишет патчи `WriteProcessMemory` и только потом продолжает процесс. Наша `dsound.dll` грузится позже и видит уже пропатченный код. Порядок нам подходит. Есть ещё путь, где лоадер в приостановленном процессе заменяет весь образ развёрнутым (`EXPANDEXE`) exe. По коду там тоже всё записывается до продолжения процесса, но вживую это не проверялось.
