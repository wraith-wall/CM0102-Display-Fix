## Что понадобилось

1. **Скачано:** `cnc-ddraw.zip` v7.1.0.0 (28.12.2024, 2 688 079 байт) с github.com/FunkyFr3sh/cnc-ddraw. GitHub не публикует для него хэш, мои SHA-256: zip `0b13ab89…bb908`, `ddraw.dll` `85e0f7d5…3a9`. Лежит в `_downloads\cnc-ddraw-v7.1.0.0\`; там же распакован комплектный `shader-package.zip` (libretro-шейдеры).
2. **Screen Mode = Full в `game.cfg` dev-копии.** В оконном режиме игра запрашивает у DirectDraw «режим» размером с рабочий стол (3840×2160×16). cnc-ddraw честно его эмулирует, и игра рисует 800×600 в углу, причём со сдвигом картинки и мыши. В режиме Full игра просит ровно 800×600, а cnc-ddraw масштабирует.
   - Формат: `u32 magic 0x1553117C, u32 flags`. **Бит `0x08` = Full, бит `0x10` = Windowed** (настройки подсвечивают их независимо, поэтому корректно ставить ровно один). Источник: вызывающий код графической инициализации передаёт `(flags >> 3) & 1` как аргумент «fullscreen» (`0x5D79D5`, `0x5D8635`).
   - Меняется только этот бит, ровно то, что делает переключатель Screen Mode в меню игры. Резервная копия исходного файла: `_logs\game.cfg.backup_before_cfg_py.bin` (`python cfg.py restore`).
   - Признаюсь в ошибке: сначала я принял за бит режима `0x10` (это номер команды сеттера) и на несколько прогонов снял не тот бит. Файл восстановлен из резервной копии байт в байт, затем выставлен правильный бит.
3. **ddraw.ini** (профиль `cnc_borderless`, остальное по умолчанию из релиза): `windowed=true, fullscreen=true, border=false` (borderless fullscreen), `maintas=true`, `renderer=opengl` (нужен для шейдеров), `singlecpu=false` (как в штатной секции cnc-ddraw для CM 99/00), `adjmouse=true`, `savesettings=0` (чтобы ini не переписывался между прогонами).

Нюансы, найденные по ходу:
- По умолчанию cnc-ddraw **запирает курсор** в окне (`ClipCursor`; освобождается по Ctrl+Tab). Из-за этого нельзя взяться за рамку или увести мышь в другое окно. `devmode=true` отключает запирание, пересчёт мыши при этом остаётся точным.

То же, что `cnc_window`, но `fullscreen=true` при `windowed=true` + `toggle_borderless=true`. Проверено: клики Game Settings → Cancel после каждого шага, режим монитора не меняется.

**Без модуля cmfix (ниже) переключатель Screen Mode в настройках игры для этого не подходит.** При выборе Windowed игра уходит в свой оконный путь: просит холст размером с рабочий стол (3840×2160×16) и рисует 800×600 в его левом верхнем углу, остальное чёрное. Это поведение игры, ini cnc-ddraw его не исправляет. `play.py` ставит Full при каждом запуске, так что достаточно перезапуска. Исправить сам переключатель можно только небольшим собственным модулем, который в памяти подменяет игре выбор режима; это вне cnc-ddraw.

## Модуль cmfix: игровой Screen Mode управляет cnc-ddraw (профиль `cnc_play_fix`, по умолчанию в `play.py`)

`_tools\cmfix\` — маленькая proxy-DLL `dsound.dll` (C, MSVC Build Tools 2026 x86, уже установлены; сборка: `build.bat`). Игра импортирует из DirectSound только `DirectSoundCreate` (ординал 1), модуль пробрасывает его в системную `dsound.dll` (проверено: `hr=S_OK`). При загрузке он ставит **два перехвата в памяти**, exe на диске не меняется:

1. **`0x5E2620`** — инициализация графики. Модуль запоминает, какой режим просит игра (Full/Windowed), и **всегда** ведёт её полноэкранным путём: игра просит 800×600, cnc-ddraw масштабирует. Затем модуль переключает cnc-ddraw в запрошенный режим (Full → весь экран 4:3, Windowed → окно с ресайзом). Переключение делается штатной комбинацией cnc-ddraw Alt+Enter через `SendInput` и только когда окно игры активно; если окно не активно, модуль ждёт. Сообщения (`PostMessage`) cnc-ddraw игнорирует, это проверено.
2. **`0x5E2EA0`** — геттер «сейчас полноэкранный режим?». По нему настройки решают, нужна ли переинициализация, на него же опираются обработка фокуса и печать. Настоящий флаг `[0xAE319C]` теперь всегда 1, и трогать его нельзя: он выбирает путь вывода кадра (`0x5E2F8D`). Поэтому геттер перенаправлен на режим, выбранный игроком.

Защита: перехваты ставятся, только если байты по обоим адресам совпадают с 3.9.68 и рядом лежит именно cnc-ddraw (экспорт `GameHandlesClose`). Иначе модуль только пробрасывает звук. Лог: `cmfix.log` в папке игры (удаляется при `wrapper.py uninstall`).

Проверка `python test_screenmode.py --start full|windowed`: старт → Full → Windowed → Full → Windowed → Alt+Enter, после каждого шага режим окна, видимость меню, клики и режим монитора. **Оба варианта 6/6 PASS.** Полный baseline-путь с модулем (Screen Mode = Windowed) тоже ok, 9/9.

Итог для игрока:
- **Screen Mode = Full** → весь экран 4:3 с полосами; **Windowed** → окно 2400×1800, тянется, содержимое масштабируется. Выбор запоминается игрой и действует при следующем запуске.
- Alt+Enter по-прежнему переключает в любой момент; игровая настройка при этом не меняется.
- Нюанс: при переключении модуль на мгновение отправляет игре Alt+Enter как нажатие клавиш. В меню и в настройках побочных эффектов не замечено.

### Кнопка «развернуть» в оконном режиме (cmfix)

**Было:** собственная логика cnc-ddraw v7.1.0.0 (`util_toggle_maximize`) переключала □ и двойной клик по заголовку между «самым большим окном 4:3 в рабочей области» (2657×1993) и **родными 800×600**. ini-опцией это не меняется: `keytogglemaximize` — только горячая клавиша (Alt+PgDn) для той же функции.

**Почему не помогал `SetWindowPos`/`ShowWindow` извне** (по исходникам v7.1.0.0): cnc-ddraw рисует в размер из своего `window_rect`, а обновляет его только сам. Ресайз мышью работает благодаря модальному циклу: `WM_ENTERSIZEMOVE` → `WM_SIZING` (останавливает поток рендера и запоминает новый клиентский прямоугольник) → `WM_EXITSIZEMOVE` (`dd_SetDisplayMode` с этим прямоугольником; заодно пересчитывается область кадра и маппинг мыши). Кроме того, cnc-ddraw перехватывает IAT всех модулей из папки игры, включая наш `dsound.dll`: `SetWindowPos`, `ShowWindow` (там `SW_MAXIMIZE` превращается в `SW_NORMAL`), `Get/SetWindowLongA`, `GetClientRect` и др. — это его подделки.

**Сделано:** cmfix сабклассит окно игры поверх текущей оконной процедуры (это `opengl32.dll`, который сам стоит поверх cnc-ddraw) и перехватывает `WM_SYSCOMMAND` `SC_MAXIMIZE`/`SC_RESTORE`, `WM_NCLBUTTONDBLCLK` по заголовку и Alt+PgDn cnc-ddraw. Разворот: внутри «псевдо-цикла» ресайза (те же три сообщения, отправленные прямо в процедуру cnc-ddraw на потоке окна) окно разворачивается настоящим `ShowWindow(SW_MAXIMIZE)`, и cnc-ddraw принимает новый размер. `dd_SetDisplayMode` всегда снимает `WS_MAXIMIZE`, поэтому бит ставится обратно, и окно остаётся развёрнутым по мнению Windows (`IsZoomed`, кнопка «восстановить»). Восстановление возвращает тот размер и позицию, что были перед разворотом (по умолчанию 2400×1800 по центру). Настоящие функции user32 берутся из таблицы экспорта напрямую, минуя перехваты cnc-ddraw. Развёрнутое окно не перетаскивается за заголовок (как и не меняет размер за рамку). Если Alt+Enter или игровой Screen Mode возвращают окно, пока оно «развёрнуто», cmfix разворачивает его снова. Сабкласс ставится, только когда сверху не собственная процедура игры: cnc-ddraw при переинициализации DirectDraw запоминает текущую процедуру как «игровую», и иначе возникла бы бесконечная рекурсия. Проверка повторяется раз в 150 мс.

**Проверка** `python test_maximize.py`: старт в окне → двойной клик по заголовку → развёрнуто → двойной клик → 2400×1800 → ресайз мышью за угол (1800×1350) → кнопка □ → развёрнуто → □ → 1800×1350 → □ → Alt+Enter (весь экран) → Alt+Enter (снова развёрнуто) → игровой Full → Windowed (снова развёрнуто) → восстановить. После каждого шага проверяются: стиль окна, `IsZoomed`, клиентская область = рабочая область 3840×2064 (клиент 3840×2019 под заголовком), кадр 4:3 по центру с чёрными полосами (2675×2019 при x=591), клики Game Settings → Cancel и неизменный режим монитора. **12/12 PASS.** Регресс: `test_screenmode.py` 6/6 в обоих вариантах, `cnc_play_fix.json` ok (9 снимков). Вручную: свернуть из развёрнутого → восстановить = снова развёрнуто, клики точные.

## Разведка: как игра рисует текст (для Phase 2b)

- `CreateFontA` / `GetTextMetricsA` / `SelectObject` / `TextOutA` вызываются в **одной функции, `0x84C830`, и это печать**: `PrintDlgA` → `StartDocA` → шрифт по `GetDeviceCaps` принтера → `StartPage` / `TextOutA` / `EndPage` → `EndDoc`. **Экранный текст GDI не использует.**
- Экранный текст игра рисует сама (программно, в поверхности через Lock/Unlock), из двух типов шрифтов в `Data\`:
  - `*.fnt` — заранее растеризованные шрифты со сглаживанием: arial 14/16/18, arial narrow 10/11, trade cond bold 24/28 (байты-градации серого);
  - `small/medium/large.t2k` — **TrueType** (sfnt 1.0, таблицы `OS/2`, `cmap`, своя `T2KG`), это шрифт «Futuristic» из настроек. Растеризуется на лету встроенным движком **T2K** (Type Solutions). Плюс `symbol.ttf`.
- Опция cnc-ddraw `anti_aliased_fonts_min_size` / `min_font_size` к этой игре не применима (она про GDI-шрифты).

**Что это значит для «настоящего чёткого текста»:**
- Простой путь (перехват шрифтов Windows) отпадает.
- Остаётся путь «перехват собственной функции вывода строки» внутри proxy-DLL: in-memory detour по адресу в exe 3.9.68, файл exe не меняется. Перехватчик записывает строку, позицию, шрифт и цвет, а при выводе кадра рисует этот текст заново в 4K поверх увеличенной картинки, растеризуя TrueType (или Arial) в нужном размере.
- Сложности: игра рисует текст в back-buffer и, вероятно, в кэшированные панели и прокручиваемые списки, а затем блитит их. Позицию текста придётся отслеживать через блиты и обрезку. Плюс нужно подавлять (или закрывать) исходный низкорезовый текст. Реализуемо, но это несколько дней работы с риском артефактов. Разумный первый шаг — короткий spike: найти функцию отрисовки строки и проверить на одном экране, что текст ложится точно.
- До этого стоит оценить, достаточно ли OmniScale/xBRZ: на сравнении они уже убирают большую часть «зерна».

## Изменения harness

- `wrapper.py install|uninstall|status|ini PROFILE` — профили `_tools\wrappers\*.json` (наследование через `extends`, ini генерируется из комплектного с переопределениями). Всё установленное записывается в `_logs\wrapper_installed.json` с SHA-256, `uninstall` удаляет ровно эти файлы. Чужие файлы не перезаписываются.
- `cfg.py show|screen full|windowed|restore` — Screen Mode в `game.cfg` (см. выше).
- Сценарии: поля `"wrapper"`, `"screen_mode"`, `"map"`, `"ref_need"`. Wrapper ставится перед запуском и снимается после.
- `input.py --map fit_aspect | fit_aspect_int`: кадр 4:3 по центру клиента (дробный или целочисленный масштаб). В этих режимах сценарий снимает экран и приводит кадр к 800×600, поэтому эталоны и координаты общие для всех вариантов.
- `compare.py` — одинаковый фрагмент из нескольких прогонов, 1:1 в физических пикселях.
- `play.py` — запуск с профилем для ручной проверки.
